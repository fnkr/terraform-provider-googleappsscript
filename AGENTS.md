# Project: terraform-provider-googleappsscript

## Commit Policy

Commit after each logical change, with a concise description of that change in the message — multi-step work gets one commit per step, not one large commit at the end. When making multiple commits in a row, make them all first, then push once.

Commit and push directly to `main` unless explicitly told otherwise.

Never add `Co-Authored-By` or any other self-attribution anywhere.

## Documentation

The README states what the provider is, how to develop and release it, and the pitfalls that make a working setup look broken. It is not an API reference, a design-rationale essay, or a changelog. Prose whose subject is a previous version of the code belongs in the commit message that changed it.

`docs/` is generated by `go generate ./...` from schema descriptions, `examples/` and `templates/`. Edit those, never `docs/` directly.

A design document describing unbuilt work is deleted when the work lands or is abandoned. Left next to the README, it reads as documentation of the system.

Keep the number of code references low. Each one is a sentence that can drift out of agreement with what it points at, and pinning hides that rather than preventing it.

Any reference to a specific place in the code — in markdown files (including READMEs), PR/issue descriptions, and PR/issue/review comments — must be a full GitHub URL pinned to a commit SHA, e.g. `https://github.com/fnkr/terraform-provider-googleappsscript/blob/<sha>/internal/provider/provider.go#L34` (`#L<start>-L<end>` for ranges). Never use bare `path:line` or branch links — branches move and the reference drifts.

## Comments

A comment says why, not what. Do not restate the line below it.

"This used to do X" is only worth keeping when doing X again is a live hazard. Otherwise it is a changelog in the wrong file.

## Code

**Constants.** A value two places must agree on is named once and referenced.

**One spelling per concept**, across Go, Terraform schema and docs. Go error strings start lowercase unless the first word is a proper noun.

**Compile patterns once.** Regexes and other expensive one-time constructions belong at package level, not inside the function that uses them, so a malformed one fails at start rather than by silently matching nothing.

## Verification

Before considering work done: `go build ./...`, `golangci-lint run`, `go generate ./...` (no diff) and `go test ./...` must all succeed.

`go test ./...` runs against an in-memory fake of the Google APIs. When the provider starts using a new API call, extend the fake. When API behavior matters, also run `TF_ACC=1 go test ./...` against the real APIs (credentials are available via Application Default Credentials) — the real APIs are eventually consistent in ways the fake is not.

Manual setup steps (Apps Script API user setting, OAuth client, consent screen, scopes) can't be verified this way — call them out explicitly in the docs rather than silently assuming they're done.
