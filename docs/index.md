# Google Apps Script Provider

Manage Google Apps Script projects, versions and deployments, including scripts bound to Google Docs, Sheets, Forms and Slides.

## Example Usage

```terraform
terraform {
  required_providers {
    googleappsscript = {
      source  = "fnkr/googleappsscript"
      version = "~> 1.0"
    }
  }
}

# Uses Application Default Credentials unless configured.
provider "googleappsscript" {}
```

## Authentication

The Apps Script API does not support service accounts, so the provider needs user credentials:

1. Turn on the Apps Script API in your [user settings](https://script.google.com/home/usersettings).
2. In a Google Cloud project, enable the **Apps Script API** and **Google Drive API**, and create an OAuth client ID of type *Desktop app*.
3. Log in with that client. The separate `CLOUDSDK_CONFIG` keeps this login out of the default Application Default Credentials, which the google provider and other tools use:

   ```sh
   CLOUDSDK_CONFIG="$HOME/.config/gcloud-appsscript" gcloud auth application-default login \
     --client-id-file=client_secret.json \
     --scopes=https://www.googleapis.com/auth/cloud-platform,https://www.googleapis.com/auth/script.projects,https://www.googleapis.com/auth/script.deployments,https://www.googleapis.com/auth/drive
   ```

4. Point the provider at the resulting file, either in the provider configuration:

   ```terraform
   provider "googleappsscript" {
     credentials = pathexpand("~/.config/gcloud-appsscript/application_default_credentials.json")
   }
   ```

   or with an environment variable:

   ```sh
   export GOOGLEAPPSSCRIPT_CREDENTIALS="$HOME/.config/gcloud-appsscript/application_default_credentials.json"
   ```

Both accept the file's path or its contents, so in CI the JSON can be passed directly from a secret.
